# ✂️ إيقاف GitHub — قائمة القطع النهائية
**تنفَّذ فقط بعد أن يثبت السيرفر عمله (خطوات التحقق بالأسفل). قبل ذلك: لا تلمس شيئاً.**

## ما الذي يتوقف على GitHub
| المشغّل | أين يوقف |
|---|---|
| تحليل كل 5 دقائق | cron-job.org: أوقف/احذف مهمة تشغيل analyze.yml |
| تحديث الصفقات كل 5 دقائق | cron-job.org: أوقف مهمة update_trades.yml |
| الماكرو كل ساعة | cron-job.org: أوقف مهمة macro_context.yml |
| التقرير اليومي | cron-job.org: أوقف مهمة daily_report.yml |
| التقرير الأسبوعي | cron-job.org: أوقف مهمة weekly_report.yml |
| بوت الاشتراكات (00:00) | GitHub → Actions → **Subscription Bot Cron** → ⋯ → **Disable workflow** |

## ما الذي يبقى على GitHub
- ✅ **Dashboard** + مهمة cron-job.org الخاصة به (اللوحة التي اخترت إبقاءها).
- ✅ اختبار CI (`tests.yml`) — يعمل فقط عند push، لا يشغّل تداولاً.
- ✅ الأدوات اليدوية (backtest / prove / run_script…) — أزرار يدوية لا تعمل إلا بضغطة؛ أبقها أو احذفها كما تريد، صفر تكلفة وهي ساكنة.
- ✅ المستودع نفسه (نسخ احتياطي + مصدر `git pull` للسيرفر).

## خطوات القطع (خلال دقائق، في وقت هادئ للسوق)
1. **أولاً**: أوقف كل مهام cron-job.org المذكورة أعلاه (ما عدا Dashboard).
2. عطّل Subscription Bot Cron من تبويب Actions.
3. **فوراً**: على السيرفر تأكد أن المهام المجدولة فعّالة:
   `schtasks /Query /TN SS_PaperAnalysis` … إلخ (كلها يجب أن تكون Ready/Running).
4. راقب لمدة ساعة:
   - Actions tab في GitHub: **لا يوجد runs جديدة** إلا Dashboard إن حان وقته.
   - تيليجرام: البطاقات مستمرة (من السيرفر الآن).
   - `logs\paper_analysis.log` على السيرفر يتحدث كل 5 دقائق.

## ⚠️ تحذير التكرار
لا يوجد أي تداخل آمن بين النظامين: كلاهما يكتب في نفس جداول Supabase ويرسل لنفس
القنوات. القطع = إيقاف GitHub **ثم** تشغيل السيرفر مباشرة، أو العكس — أبداً ليس معاً.

## خطة الرجوع (إن حدثت مشكلة على السيرفر)
1. على السيرفر: عطّل المهام سريعاً:
   `schtasks /Change /TN "SS_PaperAnalysis" /DISABLE` (كرر لكل المهام).
2. أعد تفعيل مهام cron-job.org وفعّل Subscription Bot Cron من جديد.
3. النظام يعود كما كان خلال دقائق، ثم نشخّص مشكلة السيرفر بهدوء.
